# Routes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the Storefront the document facts it lacks (canonical, Open Graph), a nav that survives mobile, a section boundary that is honest, revalidation on the Measurement Server, and a second kind of measurement for a returning visitor — without adding a second URL.

**Architecture:** A new facts file `routes.json` and a new generator `tools/build-pages.py` write one bracketed block into `index.html`'s `<head>`; everything else in the document stays hand-written. `#story` becomes its own `<section>` and the nav wraps to its own row below 700px instead of vanishing — both plain markup/CSS edits. `server.py` grows an ETag and a 304 branch for its `no-cache` rows. `lib/report.mjs` and `tools/run.mjs` learn a second, deliberately-named measurement, the **Repeat Visit**, whose Report each refuses in the other's mode.

**Tech Stack:** Python 3 (stdlib only — `json`, `pathlib`, `html.parser`), Node 20+ with `node:test`, no package manager, no framework, nothing shipped to the browser with a dependency.

**Spec:** `docs/superpowers/specs/2026-09-04-routes-design.md`

## Global Constraints

Every task's requirements implicitly include this section.

- **Nothing shipped to the browser has a dependency, and nothing a Run measures is produced at request time** (`docs/adr/0001-tooling-may-generate-what-ships.md`). Tooling may generate what ships if the output is committed and rebuilds byte-identically.
- **`tools/build-pages.py` uses the Python standard library only.** `build-images.py` and `build-icons.py` may import PIL because they rasterise; this one has no such need.
- **Never build a regex from a string.** `` `\b${name}` `` in a template literal is a backspace character, not a word boundary; it once made every attribute lookup return `undefined` while the suite reported green. Read facts through the page model or from disk.
- **Mutation-check every new assertion** by breaking the thing it guards: add a row to `tools/mutate-contract.mjs` and design the assertion against the mutation, not after it. An assertion no mutation can fail is documentation, not Lock-in.
- **Any change to `index.html` demands `node tools/build-arms.mjs`**, asserted by `tests/bench.mjs`'s `every Arm on disk is the generator applied to the control on disk`. The generator chain runs in one order: `routes.json` → `python tools/build-pages.py` → `index.html` → `node tools/build-arms.mjs` → the Arm documents.
- **Do not touch `start-cloudflare.ps1` or `start-ngrok.ps1`.** They change only when the preview workflow itself changes.
- **The tunnel this plan was written around is gone, and a new one is authorised.** The old pair
  (PID 6620/7784, `contribute-displayed-recommend-induction.trycloudflare.com`) no longer exists —
  neither PID runs, nothing listens on port 8000, and the hostname does not resolve. The user has
  authorised a fresh tunnel and will configure its new hostname in GA4. **Tasks 1-10 need no tunnel
  and must not start one**; they are entirely local. Task 11 starts it, once, after Task 10 — so
  `server.py` carries Task 7's ETag and `index.html` is final before the hostname is fixed, and the
  user configures GA4 exactly once. Tasks 5, 6 and 7 may bind `python server.py` to a local port
  for a visual check or a test, which is unrelated and is stopped again immediately.
- **Use CONTEXT.md's vocabulary** and honour its `_Avoid_` lists. A term that does not exist there yet is added there first (Task 2).
- **Commits go on `main`**, linear, single-author, no feature branch. Subjects are declarative sentences in the repo's own voice ("Make two Runs comparable: …"), never `feat:`/`fix:` prefixes.
```python
"""Write each Route's generated <head> block into its own document, as routes.json describes it.

Run from the repository root:  python tools/build-pages.py

routes.json is the one home of every Route fact -- path, file, canonical -- with two consumers:
this generator and tests/performance-contract.mjs, which holds every value written here against
the source it came from. server.py does not read it: there is one Route, already served.

This is the first generator whose source and its output are the same file. Everything outside the
two marker comments is hand-written and never touched; everything between them is written here.
Insertion is structural, never a regex over the markup: html.parser walks the document and reports
where the markers and </head> begin, which is the rigour lib/page.mjs applies in JavaScript. A
rebuild replaces what lies between the markers, so running this twice changes no byte -- and a
change to index.html still demands node tools/build-arms.mjs, as a Master's change demands its
Rungs.
"""

import json
from html.parser import HTMLParser
from pathlib import Path

ROOT = Path(__file__).resolve().parent.parent
ROUTES = json.loads((ROOT / "routes.json").read_text("utf-8"))

BEGIN = " routes.json: begin "
END = " routes.json: end "
INDENT = "  "


def escape(text):
    """What a double-quoted attribute cannot hold, and nothing else: the four the contract decodes."""
    return text.replace("&", "&amp;").replace("<", "&lt;").replace(">", "&gt;").replace('"', "&quot;")


class Head(HTMLParser):
    """Where the generated block's edges and </head> begin, as offsets into the source."""

    def __init__(self, source):
        super().__init__()
        # The first character of each line, so getpos()'s (line, column) reads as an index.
        self.lines = [0]
        for line in source.splitlines(keepends=True):
            self.lines.append(self.lines[-1] + len(line))
        self.begin = None
        self.end = None
        self.head_close = None
        self.feed(source)
        self.close()

    def at(self):
        line, column = self.getpos()
        return self.lines[line - 1] + column

    def handle_endtag(self, tag):
        if tag == "head" and self.head_close is None:
            self.head_close = self.at()

    def handle_comment(self, data):
        if data == BEGIN:
            self.begin = self.at()
        if data == END:
            self.end = self.at() + len(data) + 7  # <!-- + data + -->


def block(route):
    lines = [
        f"<!--{BEGIN}-->",
        f'<link rel="canonical" href="{escape(route["canonical"])}">',
        f"<!--{END}-->",
    ]
    return ("\n" + INDENT).join(lines)


def build(route):
    path = ROOT / route["file"]
    # newline="" on both halves: Windows would otherwise read LF and write CRLF, and every byte of
    # the document would change on a rebuild that changed nothing.
    with path.open("r", encoding="utf-8", newline="") as handle:
        source = handle.read()
    head = Head(source)
    text = block(route)
    if head.begin is not None and head.end is not None:
        written = source[: head.begin] + text + source[head.end :]
    elif head.head_close is not None:
        written = source[: head.head_close] + INDENT + text + "\n" + source[head.head_close :]
    else:
        raise SystemExit(f'{route["file"]}: no </head> to write the block before')
    changed = written != source
    if changed:
        with path.open("w", encoding="utf-8", newline="") as handle:
            handle.write(written)
    print(f'  {route["file"]:24} {"wrote" if changed else "unchanged":9} {route["path"]}')
    return changed


if __name__ == "__main__":
    written = [build(route) for route in ROUTES["routes"]]
    print(f"{len(written)} Routes from routes.json, {sum(written)} written")
```

```js
// One Lighthouse pass. `profile` is a Chrome user-data directory: two passes naming the same one
// share a profile, which is how a Worker the first installed is still installed for the second.
async function lighthousePass({ cli, url, workDir, name, profile, extra = [] }) {
  const headersFile = path.join(workDir, 'headers.json');
  const reportFile = path.join(workDir, `${name}.json`);
  await writeFile(headersFile, JSON.stringify(BYPASS_HEADERS));
  const args = [
    cli,
    url,
    '--output=json',
    `--output-path=${reportFile}`,
    '--form-factor=mobile',
    '--screenEmulation.mobile',
    `--extra-headers=${headersFile}`,
    `--only-categories=${CATEGORIES}`,
    `--chrome-flags=--headless=new --no-sandbox --user-data-dir=${profile}`,
    '--quiet',
    ...extra,
  ];
  const { code, stderr } = await finished(spawn(process.execPath, args, { stdio: ['ignore', 'pipe', 'pipe'] }));
  let text = null;
  try {
    text = await readFile(reportFile, 'utf8');
  } catch {
    // No Report at all: the exit code and stderr say why.
  }
  if (text === null) {
    throw new Error(`Lighthouse exited with code ${code} and left no Report${stderr.trim() ? `:\n${stderr.trim()}` : ''}`);
  }
  // A non-zero exit after the Report was written is chrome-launcher failing to delete Chrome's
  // temporary profile (EPERM on Windows). The Report is complete; that noise is not a reason.
  return JSON.parse(text);
}

// A working directory whose path holds no space: --chrome-flags is one space-separated string, so
// a profile directory with a space in it would reach Chrome as two flags.
async function workDirectory(prefix) {
  const workDir = await mkdtemp(path.join(tmpdir(), prefix));
  if (/\s/.test(workDir)) {
    await rm(workDir, { recursive: true, force: true });
    throw new Error(`${workDir} has a space in its path, and Chrome flags are one space-separated string; set TEMP to a path without spaces`);
  }
  return workDir;
}

// The Lighthouse adapter: the CLI this machine has installed globally, run without a shell so the
// header file path and the Chrome flags need no quoting on any platform.
export async function lighthouseMeasure(url) {
  const cli = await lighthouseCli();
  const workDir = await workDirectory('run-');
  try {
    return await lighthousePass({ cli, url, workDir, name: 'report', profile: path.join(workDir, 'profile') });
  } finally {
    // Chrome may still hold the profile's files (EPERM on Windows — the same failure
    // chrome-launcher's own cleanup retries around). A complete Report must never be lost to a
    // cleanup failure, so this retries and then gives up quietly: the directory is under the OS
    // temp root and costs nothing to leave behind.
    await rm(workDir, { recursive: true, force: true, maxRetries: 10, retryDelay: 200 }).catch(() => {});
  }
}

// The Repeat Visit adapter: two passes through one Chrome profile. The first is an ordinary
// storage-cleared navigation and its Report is thrown away -- it is there to install the Worker.
// The second keeps storage, so the Worker installed by the first serves what it kept, and that is
// the Report the Repeat Visit is.
export async function repeatMeasure(url) {
  const cli = await lighthouseCli();
  const workDir = await workDirectory('repeat-');
  const profile = path.join(workDir, 'profile');
  try {
    await lighthousePass({ cli, url, workDir, name: 'first', profile });
    return await lighthousePass({ cli, url, workDir, name: 'second', profile, extra: ['--disable-storage-reset'] });
  } finally {
    // Chrome may still hold the profile's files (EPERM on Windows — the same failure
    // chrome-launcher's own cleanup retries around). A complete Report must never be lost to a
    // cleanup failure, so this retries and then gives up quietly: the directory is under the OS
    // temp root and costs nothing to leave behind.
    await rm(workDir, { recursive: true, force: true, maxRetries: 10, retryDelay: 200 }).catch(() => {});
  }
}
```

## Revised during execution (2026-09-04)

This plan was committed with Task 1 and executed under `superpowers:subagent-driven-development`,
one subagent per task with a review after each. Three things it specifies were changed while it ran,
each because something the plan could not know turned out to be true. Recorded here because the plan
travels with the work, and a reader who follows it as written would rebuild two decisions the branch
already paid to disprove.

**1. The canonical is absolute, on an origin the table declares.** The plan and its spec both said
document-relative (`./`), reasoning that a Preview URL is random per session so there is no stable
origin to name. That reasoning was about the wrong thing: a canonical says where a page prefers to
live, not where it is being served. The Run of 2026-09-04T18:31:37Z — kept under `reports/` — read
`canonical | score 0 | Is not an absolute URL (./)` and scored **SEO 92**, eight points, while the
Performance Contract was asserting the relative form was correct. The contract and the audit wanted
opposite things and the Report is what noticed. `routes.json` gained a `site` key,
`https://field-notes-supply.example` (a reserved host, deliberately not a Preview URL), every
Route's canonical is pinned to that origin, and `lib/page.mjs` reads a canonical as a named fact of
the page rather than a reference, so the self-hosted rule never sees it. The spec is corrected in
place.

**2. The Repeat Visit goes through Lighthouse's Node API, not two CLI passes.** The plan specified
two CLI runs sharing a `--user-data-dir` passed through `--chrome-flags`. That mechanism cannot
work, and fails silently: Chromium honours the **first** `--user-data-dir` it is given, and
chrome-launcher pushes its own temp profile before appending anything from `--chrome-flags`. The
first implementation was correct against the plan and measured a first visit twice; the Report that
did so (2026-09-04T19:04:21Z) is kept beside the one that worked, and `lib/report.mjs` now marks any
Repeat Visit whose every request came down in full, because that is what this failure looks like
from the outside. `9ba7576` is the rewrite: one browser launched with `userDataDir` set, two
navigations, the second with `disableStorageReset`.

**3. Six mutation rows beyond the plan's 49.** M53 (a protocol-relative canonical), M54 (a canonical
on another origin — restoring coverage that rewriting M42 had silently removed), M55 (a second
canonical link, which is what finally put a mutation behind an assertion that had counted them since
Task 3 with nothing able to fail it), and three more from the task reviews. The harness reads 55/55.

Two further findings from the final review are recorded rather than fixed, per this repository's own
rule that a review's findings go to `BACKLOG.md` and planning starts from that list: **D33** (two
generated-block assertions no mutation isolates) and **D34** (the Chrome flags are the one
measurement literal `MEASUREMENT` does not unify).
