# Make the Storefront a full PWA

## Context

The Storefront is the page under test in a Core Web Vitals lab. Everything around it exists to
measure it, improve it, and stop the improvement from quietly reverting. You asked for full PWA
features and for everything that can work offline to work offline, on a Storefront you described as
the core of a product that will grow — so the work has to arrive the way every capability in this
repo arrives: shipped, then locked in.

Three facts shape the whole design.

**This cannot be a Win.** Lighthouse 13.4.1 has no PWA category — it was removed in v12, and the Run
requests only `performance,accessibility,best-practices,seo` (`tools/run.mjs:24`). The reference
Report contains no `installable-manifest`, `themed-omnibox`, `apple-touch-icon` or `tap-targets`
audit. CONTEXT.md:30-33 defines a Win as a change a Run shows moved a metric, so by this repo's own
vocabulary a PWA can only ever be a **non-regression**. The Performance Contract, not the Report,
has to be what holds it in place. `BACKLOG.md` must say this in those words from the first commit.

**A Worker is the one addition that can corrupt a Run.** `server.py` is the Measurement Server
precisely because its cache headers are part of what is measured; a Worker inserts a second cache in
front of them. Verified in the reference Report: `disableStorageReset: false` and `clearStorageTypes`
contains `service_workers` and `cache_storage`, so the Worker installs and activates **fresh on
every Run**. That makes two things true at once — the Run is safe by default, and it is one CLI flag
away from silently recording a fake result.

**The lab's headline is 7 requests and 32.3 KB.** Verified from the reference Report's
`network-requests`: `/` 3,024 · `hero-768.webp` 6,746 · `app.v1.min.js` 302 · `notebook-400.webp`
5,982 · `mug-374.webp` 1,992 · `coffee-374.webp` 13,492 · `favicon.ico` 1,488. Note what is *not*
there: `hero-640.webp`, `hero-1200.webp` and `notebook-700.webp`. Precaching every Rung would add
three requests and 52.7 KB of pure waste to the number CLAUDE.md:112-120 quotes as the state of the
art. The Shell is sized against this list, not against a wish.

### Decisions taken, with reasons

- **The Run must not move**, and I take it myself — starting `./start-cloudflare.ps1` in the
  background and reading the hostname it prints. Registration is deferred to `load` →
  `requestIdleCallback({timeout: 500})`. Not a multi-second `setTimeout`: pushing registration past
  network-idle to dodge the measurement is exactly what this lab exists to forbid.
- **Icons are placeholders**, drawn as pure geometry by `tools/build-icons.py` (Pillow 12.3.0) so
  rebuilds are byte-identical, Generation-stamped (`icon-v1-192.png`) so serving them `immutable` is
  honest, and living in a new `icons/` directory — never `images/`, whose contents are asserted
  set-equal to Masters + Rungs (`tests/performance-contract.mjs:208-215`).
- **There is no `icons.json`.** `images/slots.json` exists because markup cannot be a build input. A
  manifest *is* a data file, so `manifest.webmanifest` becomes the one home of every icon fact, with
  three consumers: the generator, the contract, and the browser. One table fewer than slots.json, and
  no agreement assertion needed between two of our own files.
- **`app.v1.min.js` is kept on disk** and dropped from the allowlist. CONTEXT.md:47 states the rule
  ("superseded Generations are kept, not deleted"); CLAUDE.md:57-59 records a past deletion. A stated
  rule outranks a record of one occasion. The contradiction goes to `BACKLOG.md` rather than being
  resolved unilaterally here.
- **Vocabulary is coined before code**, and the existing avoid-lists bind it. CONTEXT.md:58 bans
  "app", "store", "shop", "demo"; CONTEXT.md:63 bans "banner". So the element is a **Notice**, never
  a banner, and its copy reads "Add to Home screen", never "Install app".

## The vocabulary this work introduces

Coined in CONTEXT.md in the voice of the existing entries, each with its `_Avoid_` list, **before**
any code is written:

- **Worker** — the script that stands between the Storefront and the network. _Avoid_: service
  worker (in prose), sw, cache layer.
- **Shell** — the set of URLs the Storefront needs to render with the network gone. _Avoid_:
  precache, app shell, bundle.
- **Notice** — the one element that offers to add the Storefront to the home screen, and later
  offers the newer Generation. _Avoid_: banner, prompt, toast, modal.

## The four defects this design exists to avoid

**1 · A `hidden` Notice that ships visible.** `[hidden]{display:none}` lives in the UA stylesheet, so
any author rule setting `display` wins on origin — and `index.html` carries no `[hidden]` rule today
(verified: zero occurrences). `.notice{position:fixed;display:flex}` would ship the Notice visible on
every load, putting `target-size` (w7), `color-contrast` (w7) and `button-name` (w10) in play against
an accessibility score that is currently 100. This is the same class of bug CLAUDE.md:81-86 already
documents for `height` vs `aspect-ratio`. The stylesheet carries `[hidden]{display:none!important}`,
and the assertion is a cascade check across every `styles.contexts` entry — not a trivial "the
element has the attribute". The Notice is invisible to every Run (`beforeinstallprompt` never fires
in Lighthouse's headless profile), so only the Contract can ever hold it to account; that is the
argument for keeping its markup and CSS in `index.html`, inside the page model, rather than building
it in JS.

**2 · A page that reloads mid-Run.** Storage is cleared before every Run, so the Worker installs and
activates fresh each time. Add `clients.claim()` and it claims the page, fires `controllerchange`,
and a naive one-shot reload listener reloads the page in the middle of the trace — every Run, not as
a flake. Three defences, all three taken: no `clients.claim()` in `sw.js`; a
`const hadController = !!navigator.serviceWorker.controller` guard captured at script start; and an
assertion that `sw.js` contains no `clients.claim()` and no `skipWaiting()` outside the `message`
handler, with a mutation row that adds one and watches it go red.

**3 · A Shell that triples the byte count.** See the request list above. The Shell is
`['./', './app.v2.min.js', './favicon.ico']` — `./` is the only net-new request, because
`cache.addAll` consults the HTTP cache and the other two are already immutable hits. Images are
**runtime cache-first on `/images/`**, which is the more honest offline story, not a lesser one:
every image the visitor actually saw is theirs offline, and one they never saw never was. The
manifest is not in the Shell (you cannot install while offline); icons and screenshots are not
either (the OS install pipeline fetches those, not the page). Expected landing: 7 → 9-10 requests,
32.3 → ~37 KB.

To still reach "everything offline", the Worker accepts a `{type:'TOP_UP'}` message that fills in
every remaining Rung — and `app.v2.min.js` sends it **only when `navigator.serviceWorker.controller`
already exists**, i.e. only to a returning visitor. During a Run storage is cleared, so the page is
never controlled and the top-up never fires. That must be written down as *a first-time visitor
genuinely is not a returning one*, or it reads as gaming the measurement.

**4 · A deprecation that costs 6 of 25 best-practices points.** Chrome reports
`<meta name="apple-mobile-web-app-capable">` as a deprecation issue; `deprecations` is w5 and
`inspector-issues` w1 out of 25, so landing in both reads 76. Ship
`<meta name="mobile-web-app-capable" content="yes">` **only**, and check the DevTools Issues panel
through the tunnel before trusting best-practices 100. Related: `errors-in-console` is w1, and a
`sw.js` served with the wrong content type registers-and-fails silently into it — which the server
assertion covers.

## Design notes

**`server.py` reshapes rather than gains an override.** Caching has always been a property of the
URL, not the bytes, so the fact moves instead of being duplicated:

```python
POLICY      = {suffix: (content_type, gzip)}                        # facts about the bytes
PUBLIC      = {path: (file, cache)}                                 # facts about the URL
DIRECTORIES = {"/images": (IMAGES, IMAGE_NAME, IMMUTABLE),
               "/icons":  (ICONS,  ICON_NAME,  IMMUTABLE)}
```

The docstring earns a truer sentence: *an Immutable Asset's filename is its cache key, and `sw.js` is
the one script in the lab whose filename is deliberately not one — a registration is identified by
its URL, so a Generation-stamped Worker would be a second registration, not a replacement.* The
unguarded `POLICY[suffix]` at `server.py:85` is fixed with a **boot-time invariant**, not a 404: a
public path with no policy row is a programming error, and a 500 mid-Run is a corrupted measurement.
`tests/measurement-server.mjs:39-42` already surfaces an early exit with its stderr.

**`lib/page.mjs` gains `manifest`, and nothing else.** Adding `manifest` to the `rel` alternation at
`page.mjs:147` is the obvious move and a trap: the sweep at `tests/measurement-server.mjs:173-174`
demands every `page.assets` entry be `immutable`, and the manifest must be `no-cache`. The other
repairs — splitting `assets`, or special-casing in the test — push a server concept into the page
model. The page model already carries one-off named facts (`title`, `meta`, `pictures`, `scripts`),
so a resolved `manifest` href (or `null`) is one more, and the server sweep gains one line probing it
for 200 / `no-cache` / `application/manifest+json`. `<link rel="apple-touch-icon">` needs no
special handling — `\bicon\b` matches inside it, so it joins `assets` and is genuinely immutable.

**`lib/service-worker.mjs` is the one parser of the Worker.** A regex over `sw.js` inside the contract
would be a second parser in the wrong layer, against `lib/page.mjs:1-5`'s stated rule. It exposes
`{ shell, cacheName, generation, claimsClients, skipsWaitingAtInstall }` so the contract reads
values, not bytes. (Making `sw.js` an ES module so Node could import it does not work — top-level
`self.addEventListener` throws in Node.)

**The cache name tracks the Generation of the script named inside `SHELL`**, not the Worker's own.
Those are independent axes: a Rung rebuild changes what is cached without changing `sw.js`. `activate`
deletes every cache that is not the current name — and the comment must say this pruning only bounds
growth, since every Shell entry but `./` is a content-addressed immutable URL and stale copies are
harmless.

## Phases

Assertion-first throughout: write the red assertion, then the code, then the gate.

**P0 · Vocabulary and baseline.** Worker, Shell and Notice into CONTEXT.md. The reference Run's
figures into `BACKLOG.md` as the "before", framed as a non-regression, not a Win.
→ `node --test "tests/**/*.mjs"` and `node tools/mutate-contract.mjs` both green. This establishes the
floor; `tools/mutate-contract.mjs:49` refuses to run without it.

**P1 · `server.py` reshape — pure refactor, no new URLs.** Cache moves from POLICY to PUBLIC;
`IMAGE_NAME` folds into `DIRECTORIES`; the boot-time invariant lands. Not one assertion changes.
→ `node --test tests/measurement-server.mjs`. Unchanged assertions passing is the strongest evidence
the reshape changed nothing.

**P2 · Icons.** PNG (IHDR) support in `lib/image-size.mjs` first, red; its docstring and the
`'not a JPEG or WebP'` message at `:56` both become lies otherwise. Then `tools/build-icons.py`
drawing from the manifest's own colours, `icons/` populated, the `.png` policy row and `/icons/`
directory row, `/icons/` added to the hidden list. Assertions: `icons/` holds nothing but what the
manifest declares (the `images/` sweep is the template); every icon's real pixels match its declared
`sizes`; screenshots satisfy Chrome's rules — 320-3840 px, max ≤ 2.3× min, one aspect ratio per
`form_factor` — which is what makes keeping them defensible rather than decorative.
→ `node --test tests/performance-contract.mjs`, then `node --test tests/measurement-server.mjs`

**P3 · Manifest and head links.** `page.manifest` in `lib/page.mjs`, red first. Then
`manifest.webmanifest` (`display: "standalone"`, `id: "/"`, `scope: "./"`, `start_url: "./"`), the
`rel="manifest"` and `rel="apple-touch-icon"` links, `theme-color`, and `mobile-web-app-capable` —
not the `apple-` prefixed one. No PNG `rel="icon"` links: they would change which favicon request the
Run records. Assertions: name/short_name/description agree with `<title>` and the meta description;
`lang` agrees with `<html lang>`; `theme_color`/`background_color` equal `--ink`/`--paper` through
`styles.cascade(':root')` + `resolve`; the `theme-color` meta agrees with the manifest; `shortcuts`
cover exactly the in-page `#` routes (`tests/performance-contract.mjs:236` is the pattern); no
avoid-list word appears in any user-visible string.

**P4 · Generation v2 and the Notice — no Worker yet.** `app.v2.min.js`: the Bag, the Notice UI,
`beforeinstallprompt` (listener attached **eagerly** — deferring it misses the event), `appinstalled`,
localStorage dismissal. `index.html` points at v2 and carries the Notice markup, its CSS, and
`[hidden]{display:none!important}`. v1 leaves PUBLIC. Assertions: the `hidden` cascade check across
every context; the Notice resolves to `position:fixed` everywhere (out of flow, so revealing it
shifts nothing — zero CLS by construction); Notice text clears 4.5:1 against its own background,
mirroring `tests/performance-contract.mjs:110-116`, because no Run will ever check it;
`page.scripts.length === 1` still holds because registration lives inside the one script; and
`/app.v1.min.js` is now 404, which is what makes dropping it from PUBLIC load-bearing. Fix
`tests/measurement-server.mjs:82,87` to name v2, and add the missing `assert.equal(res.status, 200)`
at `:158` — that test requests v1 today and would pass green against a 404, hiding the break.
→ `node --test tests/performance-contract.mjs`, then `node --test tests/measurement-server.mjs`

**P5 · The Worker.** `lib/service-worker.mjs` first, then `sw.js`: the three-entry Shell, cache-first
`/images/` and `/icons/`, network-first with cache fallback for `./`, the manifest and the crawler
files, the guarded `TOP_UP` handler, no `clients.claim()`, no install-time `skipWaiting()`, `activate`
